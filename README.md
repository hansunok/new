# 개인레슨 아티스트 홈페이지 · 레슨 관리

빌드 도구 없이 동작하는 정적 사이트 + Supabase 백엔드. 기획은 [CLAUDE.md](CLAUDE.md) 참고.

## 현재 구현 (권장 개발 순서 1~2단계)
- `index.html` — 아티스트 홈페이지(프로필, 레슨 안내, 포트폴리오, 공지·후기, 레슨/상담/체험 신청, 연락 채널)
- `admin/` — 아티스트 로그인, 신청 접수 관리, 수강생 명단(등록·수정·상태 관리), 신청 → 수강생 전환
- `supabase/schema.sql` — 전체 기능(일정·출결·수강권·결제·레슨 기록·RLS)의 DB 스키마. 3~6단계 화면은 이 위에 추가합니다.

## 설정
1. Supabase 프로젝트 생성 → SQL Editor에서 `supabase/schema.sql` 실행 (이미 일부 실행했다면 `supabase/migrations/`의 빠진 번호만 순서대로)
2. `js/config.js`에 Project URL / anon key 입력
3. 로컬 확인: `python serve.py` 후 http://localhost:8000 (관리자: `/admin/`)
4. 배포: GitHub Pages 등 정적 호스팅 후 `js/config.js`의 `siteUrl`에 주소 입력

## 여러 아티스트
- 아티스트는 `/admin/`에서 이메일·비밀번호로 **새 아티스트 가입** → 활동명과 홈페이지 주소(slug)를 정해 자신의 사이트를 만듭니다.
- 각자의 홈페이지: `index.html?a=<slug>` (예: `index.html?a=kim-vocal`). `?a=`가 없으면 `config.js`의 `artistSlug`를 보여줍니다.
- 사이트 내용(소개·레슨 안내·문의 채널)은 관리자 **사이트 정보** 탭에서 편집하며 DB에 저장됩니다.
- 모든 데이터는 아티스트별로 분리됩니다(RLS). 다른 아티스트의 수강생·결제·일정은 볼 수 없습니다.

## 아티스트 승인제
- 새로 가입한 아티스트는 **승인 대기**입니다. 승인 전에는 홈페이지가 공개되지 않고 관리 기능도 쓸 수 없습니다.
- 승인은 **플랫폼 관리자**가 관리자 페이지 맨 위 "플랫폼 관리" 표에서 합니다. (승인 / 정지 / 다시 승인)
- 최초 플랫폼 관리자는 SQL Editor에서 한 번 지정합니다.
  ```sql
  insert into platform_admins (user_id) select id from auth.users where email = '운영자@이메일';
  ```
- 아티스트가 스스로 승인 상태를 바꾸는 것은 DB 트리거가 막습니다.

## 공연·영상·메시지 발송·신청 영역 설정
- SQL Editor에서 `supabase/migrations/`의 003, 004를 순서대로 실행합니다. (002도 아직이면 먼저)
- 문자 속 공연 링크(`event.html`)는 배포된 주소여야 받는 사람이 열 수 있습니다. 배포 후 `js/config.js`의 `siteUrl`에 홈페이지 주소를 넣으세요.
- 관리자 **공연** 탭: 공연 등록 → 홈페이지 '공연 일정'에 표시
- 관리자 **영상** 탭: 유튜브 주소 입력 → 홈페이지 '포트폴리오 · 공연 영상'에서 재생
- 관리자 **홈페이지 설정** 탭: 레슨 신청 영역 표시/숨김 (끄면 서버에서도 신청 차단)
- 관리자 **메시지 발송** 탭: 받는 사람 선택 → 공연 선택 + 추가 내용 입력 → 포스터 포함 미리보기 확인 → 버튼 클릭으로 발송 (자동 발송 없음)
  - 발송 방법: "번호·내용 복사"(카카오톡·문자앱에 붙여넣기) 또는 "문자앱으로 열기"(휴대폰). 사용 시 발송 이력에 기록됩니다.
